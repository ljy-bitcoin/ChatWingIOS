# 爱思免费签名兼容修复（待真机验证）

适用：本次检查的爱思签名包，主程序与扩展的钥匙串授权均为同一团队前缀的通配分组，且没有 App Groups 权限。

## 上传步骤
1. 解压本补丁。打开 GitHub 的 ChatWingIOS 仓库首页（Code）。
2. Add file → Upload files，将解压后的 Shared、Broadcast、Docs 三个文件夹拖入上传区。不要拖最外层 ChatWing-FreeSigning-Fix 文件夹。
3. 检查列表路径应是 Shared/Keychain.swift、Shared/SharedStore.swift、Broadcast/SampleHandler.swift、Docs/FreeSigningTest.md。点击 Commit changes。
4. Actions → Build iPhone IPA → Run workflow → main。不要对之前的旧运行点 Re-run。
5. 新运行成功后下载 ChatWing-iPhone-IPA，解压得到 IPA，再用原来的爱思账号签名。保留录屏和键盘扩展，安装新包。

## 验证顺序
1. 打开聊伴，在“接口”填写接口地址、模型和密钥，保存。确认不再出现 -34018。
2. 退出并重新打开 App，确认配置和密钥能读取。
3. 先在“识别与测试”做手动文字测试，确认 API 返回候选回复。
4. 保存配置并开启分析，启动录屏。扩展必须能够读到主程序配置，否则会明确报错并结束广播。
5. 开启画中画，再切到联系人名称匹配的微信聊天。确认广播状态更新、OCR 识别和回复更新。
6. 在系统设置中为聊伴键盘开启完全访问，确认候选回复可读取；暂停后不再使用旧会话的结果。
7. 避免在主程序、键盘同时点开启/暂停；钥匙串兼容通道对并发控制采用最后一次写入生效。

## 改动与边界
- 保留 App Groups 正常签名路径；缺少共享容器时，使用系统认可的共享钥匙串组存储小量 JSON。
- 从系统钥匙串返回的实际分组解析签名前缀，而不是写死用户账号或信任描述文件的内容。系统拒绝共享分组时会报错，不尝试绕过权限。
- 主程序和录屏扩展的 API 密钥使用相同兼容分组。键盘共享结果与控制状态。
- 单条共享记录上限为 512 KiB；会话 UUID 与过期检查继续拒绝旧结果。
- 静态结构检查通过：4 targets、13 Swift 文件、164 PBX 引用。Swift 语法解析通过。
- 当前环境无 Xcode，尚未进行本版本的 Apple SDK 编译、真机共享验证和后台耗电测试。必须由 GitHub Actions 编译以及上述手机步骤验证；不能把补丁视作已验证的完整修复。
- 如果出现“录屏扩展无法读取主程序配置”，请提供该错误及此次重签名后的 IPA。保存成功只证明主程序能访问，不等于扩展共享成功。
